## 一、镜像链拓扑（跳过数据源）

```
iOS Kazumi
  → http://<ECS>:31033            (公网 frp 隧道入口, 地址见 镜像隧道/frpc.toml serverAddr)
  → PC frpc.exe                   (计划任务 KazumiSkipMirror 开机启动, 转发到 127.0.0.1:8899)
  → skip_proxy.dart :8899         (本地反代: X-Skip-Token 鉴权 + 路由白名单)
  → Clash 127.0.0.1:7897          (出站代理)
  → api.aniskip.com / graphql.anilist.co
```

## 二、组件清单与启动方式

| 组件 | 位置 | 启动方式 | 日志 |
|---|---|---|---|
| frpc | 镜像隧道/frpc.exe | 计划任务 `KazumiSkipMirror`(onstart, SYSTEM) | 镜像隧道/frpc.log |
| 反代 | 镜像隧道/skip_proxy.dart | 计划任务 `KazumiSkipMirrorWatchdog`（每 5 分钟, 经 autostart.vbs→bat, **内置单实例守卫**） | 镜像隧道/proxy.log |
| Clash | Clash Verge | 用户手动/自启（**反代出站强依赖它**） | — |
| 端口 | 反代 8899 / Clash 7897 / frp 31033(跳过)+31034(veilplay) / FS 8191 | — | — |

**重启反代**（改了 skip_proxy.dart 后）：
```powershell
Get-CimInstance Win32_Process -Filter "Name='dart.exe'" |
  Where-Object { $_.CommandLine -like '*skip_proxy*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
# 然后等 watchdog ≤5 分钟自动拉起, 或手动: cmd /c 镜像隧道\skip_proxy_start.bat
```

## 三、iOS 跳过失效故障树（按序检查，实测案例在括号内）

```
0. PC 开机且未睡眠? (睡眠冻结一切, 看门狗无能为力 — 事件查看器查 Id=42)
1. frpc 进程在? tasklist | grep frpc
   └ 不在 → 计划任务问题 → 手动跑 镜像隧道\frpc_start.bat
2. 反代 8899 在听? netstat -ano | grep ":8899" | grep LISTENING
   └ 不在 → 手动跑 skip_proxy_start.bat
3. 带token本地探针通不通 (期望 404/200, 403=token错):
   curl -H "X-Skip-Token: <skip_proxy.dart 第12行的值>" \
     "http://127.0.0.1:8899/skip/aniskip/v2/skip-times/21/1?episodeLength=1420&types=op&types=ed"
4. 公网隧道通不通 (同样探针, 域名换 frpc.toml 的 serverAddr:31033)
5. Clash 活着? tasklist | grep mihomo
   └ 反代日志(proxy.log)里 502 = Clash 出站挂
6. iOS 端: 改过镜像配置必须【杀后台重开】(运行中进程用内存旧值 — 实际踩过)
7. proxy.log 有请求但 403 → token-fp 指纹比对 (反代已内置指纹日志)
   ⚠ proxy.log 无时间戳 (auth-fail 行除外)
```

## 四、反代路由与鉴权要点

- 路由白名单（skip_proxy.dart `routes`）：`/skip/aniskip`(GET) / `/skip/anilist`(POST)
- 鉴权：`X-Skip-Token` 头 = skip_proxy.dart 第 12 行 `accessToken`；iOS 端设置里的
  「跳过数据源镜像 token」必须与之一致
- 反代出站**必须经 Clash**（`upstreamProxy = PROXY 127.0.0.1:7897`）——Clash 停 = 出站断

## 五、源死活诊断决策树（某源搜不出/播不了时）

```
1. curl 直接探 searchURL (带浏览器 UA)
   ├ 000/超时 → 站点死/被墙 → 判「等恢复」或换域名 (参照 mutefun 先例)
   ├ 403 → CF 挑战 → 确认规则带 webviewFetch → 真机 QA 验证
   ├ 404 → 站点改版 → 找新路径 (对照首页表单/站点 schema)
   └ 200 + 小体积(<2KB) → JS 壳页 (雷池 WAF) → 需 WebView 路径
2. 200 + 真页面 → 检查规则选择器是否匹配当前 DOM
   └ 对照素材: site_diag/ (FS 抓) 或 site_diag_render/ (真机渲染转储)
3. ⚠ 假阴性三连 (本项目反复踩):
   a. 扫描工具 10s 超时对慢站/FS 兜底站不够 (樱花 95 对全假的教训)
   b. 传错 episodeLength 会 404 (aniskip 片长敏感, ±40-60s 窗口)
   c. 中文关键词直查 AniList 必失败 (索引是罗马字, app 生产路径用原名)
   → 存疑时用真机 QA 驱动做最终裁决
```

## 六、代理白名单机制（network_config.dart）

- **内置白名单**：`_proxyWhitelistHosts`（aniskip/anilist/gugu3/xfdm.pro 等 + 用户设置 `proxyWhitelistExtra` 逗号分隔追加）
- 语义：只有白名单域名走 Clash，其余全部直连（含视频流）
- 新源需要代理时：追加到用户设置（app 设置→代理）或内置常量
- 检查某域名走不走代理：`_shouldProxyHost`（network_config.dart）
